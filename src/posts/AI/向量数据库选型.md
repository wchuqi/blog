# 向量数据库选型与实践
> 原理是通用的，工具是具体的——本文帮你选对工具、用对工具、避坑上线。
**Category**: AI 基础设施 / 工具与实践
**Difficulty**: Intermediate
**Prerequisites**: [向量数据库原理](向量数据库原理.md)（向量、相似度度量、ANN 索引算法的基本概念）

## 全景对比

### 主流向量数据库一览

| 工具 | 类型 | 开发语言 | 开源 | 托管云 | 最佳场景 |
|------|------|---------|------|--------|---------|
| **Chroma** | 嵌入式 | Python | ✅ | ❌ | 快速原型、学习 |
| **Qdrant** | 独立服务 | Rust | ✅ | ✅ | 生产环境、高性能 |
| **Milvus** | 分布式 | Go/C++ | ✅ | ✅ (Zilliz) | 大规模企业级 |
| **Weaviate** | 独立服务 | Go | ✅ | ✅ | 混合搜索 |
| **Pinecone** | 全托管 SaaS | 闭源 | ❌ | ✅ | 零运维 |
| **pgvector** | PG 扩展 | C | ✅ | ✅ (各 PG 云) | 已有 PG 基础设施 |
| **LanceDB** | 嵌入式 | Rust | ✅ | ✅ | 多模态、列式存储 |
| **FAISS** | 库（非数据库） | C++/Python | ✅ | ❌ | 算法研究、自定义管线 |

### 核心能力对比

| 能力 | Chroma | Qdrant | Milvus | Weaviate | pgvector | Pinecone |
|------|--------|--------|--------|----------|----------|----------|
| **全文搜索** | ❌ | ✅ | ✅ | ✅⭐ | ✅ (tsvector) | ❌ |
| **混合搜索** | ❌ | ✅ (RRF) | ✅ | ✅⭐ | 需手动融合 | ❌ |
| **元数据过滤** | ✅ | ✅⭐ | ✅ | ✅ (GraphQL) | ✅ (SQL) | ✅ |
| **动态 Schema** | ✅ | ✅ | ✅ | ✅ | ❌ (需 ALTER) | ✅ |
| **多向量字段** | ❌ | ✅ | ✅ | ✅ | 需多列 | ❌ |
| **分布式** | ❌ | ✅ (云) | ✅⭐ | ✅ (云) | ❌ (需 Citus) | ✅ (自动) |

> ⭐ 表示该工具在该能力上表现特别优秀。

## 工具详解

### Chroma——最简单的入门选择

**一句话**：零配置的嵌入式向量数据库，5 分钟上手。

**适用场景**：学习向量搜索概念、快速原型验证、小规模本地应用。

**不适用场景**：生产环境、大规模数据、需要持久化和高可用。

```bash
pip install chromadb
```

```python
import chromadb

# 1. 创建客户端（内存模式）
client = chromadb.Client()

# 2. 创建集合
collection = client.create_collection(
    name="my_documents",
    metadata={"hnsw:space": "cosine"}  # 使用余弦相似度
)

# 3. 添加文档（Chroma 内置了默认 embedding 模型）
collection.add(
    documents=[
        "Python 是一种解释型、面向对象的高级编程语言",
        "JavaScript 是 Web 前端开发的核心语言",
        "机器学习是人工智能的一个子领域",
        "深度学习使用多层神经网络来学习数据表示",
        "向量数据库专门用于存储和检索高维向量",
    ],
    ids=["doc1", "doc2", "doc3", "doc4", "doc5"],
    metadatas=[
        {"category": "programming", "language": "python"},
        {"category": "programming", "language": "javascript"},
        {"category": "ai", "subfield": "ml"},
        {"category": "ai", "subfield": "dl"},
        {"category": "database", "type": "vector"},
    ]
)

# 4. 语义搜索
results = collection.query(
    query_texts=["人工智能相关的技术"],
    n_results=3
)

# 5. 查看结果
for i, (doc, dist) in enumerate(zip(results["documents"][0], results["distances"][0])):
    print(f"#{i+1} (距离: {dist:.4f}): {doc}")
```

**输出**：
```
#1 (距离: 0.1523): 机器学习是人工智能的一个子领域
#2 (距离: 0.1891): 深度学习使用多层神经网络来学习数据表示
#3 (距离: 0.3245): 向量数据库专门用于存储和检索高维向量
```

> 💡 注意：即使查询文本中没有出现"机器学习"、"深度学习"这些关键词，语义搜索也能找到它们——这就是向量搜索的威力。

**持久化模式**：

```python
# 数据持久化到磁盘
client = chromadb.PersistentClient(path="./chroma_db")

# 也可以指定自定义 embedding 模型
from chromadb.utils.embedding_functions import SentenceTransformerEmbeddingFunction
ef = SentenceTransformerEmbeddingFunction(model_name="BAAI/bge-large-zh-v1.5")
collection = client.create_collection("my_docs", embedding_function=ef)
```


### Qdrant——生产级高性能选择

**一句话**：Rust 实现的高性能向量数据库，API 友好，功能全面。

**适用场景**：中等规模生产环境、需要丰富过滤条件、混合搜索。

**不适用场景**：超大规模分布式（> 10 亿向量，考虑 Milvus）。

```bash
# Docker 启动
docker run -p 6333:6333 -p 6334:6334 \
    -v $(pwd)/qdrant_storage:/qdrant/storage \
    qdrant/qdrant
```

```bash
pip install qdrant-client openai
```

```python
from qdrant_client import QdrantClient
from qdrant_client.models import (
    Distance, VectorParams, PointStruct,
    Filter, FieldCondition, MatchValue,
    MatchAny, Range
)
from openai import OpenAI

# --- 初始化 ---
qdrant = QdrantClient("localhost", port=6333)
openai_client = OpenAI()

COLLECTION_NAME = "knowledge_base"

# --- 1. 创建集合 ---
qdrant.recreate_collection(
    collection_name=COLLECTION_NAME,
    vectors_config=VectorParams(
        size=1536,                # text-embedding-3-small 的维度
        distance=Distance.COSINE
    )
)

# --- 2. 准备数据并插入 ---
def get_embedding(text: str) -> list[float]:
    response = openai_client.embeddings.create(
        model="text-embedding-3-small",
        input=text
    )
    return response.data[0].embedding

documents = [
    {
        "id": 1,
        "text": "Qdrant 是一个用 Rust 编写的高性能向量数据库，支持丰富的过滤条件。",
        "source": "docs/qdrant-intro.md",
        "category": "database"
    },
    {
        "id": 2,
        "text": "RAG（检索增强生成）通过在生成前检索相关文档来增强大语言模型的回答质量。",
        "source": "docs/rag-overview.md",
        "category": "ai"
    },
    {
        "id": 3,
        "text": "HNSW 算法通过构建多层可导航小世界图来实现高效的近似最近邻搜索。",
        "source": "docs/hnsw-algorithm.md",
        "category": "algorithm"
    },
]

# 批量获取 embedding 并插入
points = []
for doc in documents:
    embedding = get_embedding(doc["text"])
    points.append(PointStruct(
        id=doc["id"],
        vector=embedding,
        payload={
            "text": doc["text"],
            "source": doc["source"],
            "category": doc["category"]
        }
    ))

qdrant.upsert(collection_name=COLLECTION_NAME, points=points)

# --- 3. 搜索（带过滤） ---
query_vector = get_embedding("向量数据库的索引原理")

results = qdrant.search(
    collection_name=COLLECTION_NAME,
    query_vector=query_vector,
    limit=3,
    query_filter=Filter(
        must=[
            FieldCondition(
                key="category",
                match=MatchAny(any=["database", "algorithm"])  # 多值匹配
            )
        ]
    )
)

for hit in results:
    print(f"得分: {hit.score:.4f}, 文本: {hit.payload['text'][:50]}...")
```

**Qdrant 独特优势**：

```python
# 1. Payload 索引（加速元数据过滤）
qdrant.create_payload_index(
    collection_name=COLLECTION_NAME,
    field_name="category",
    field_schema="keyword"
)

# 2. 搜索分组（避免结果过于集中）
from qdrant_client.models import SearchGroupsRequest
groups = qdrant.search_groups(
    collection_name=COLLECTION_NAME,
    query_vector=query_vector,
    group_by="source",  # 按来源分组，每个来源最多返回 2 条
    limit=3,
    group_size=2
)

# 3. 推荐 API（基于已有结果找相似）
recommendations = qdrant.recommend(
    collection_name=COLLECTION_NAME,
    positive=[1, 2],    # 喜欢这些
    negative=[5],       # 不喜欢这些
    limit=5
)
```

**适用场景**：大规模企业级部署、需要水平扩展、高吞吐写入。

**不适用场景**：小项目（杀鸡用牛刀）、不想运维分布式系统。

```python
from pymilvus import (
    connections, Collection, CollectionSchema,
    FieldSchema, DataType
)
import numpy as np

# --- 连接 ---
connections.connect("default", host="localhost", port="19530")

# --- 定义 Schema ---
fields = [
    FieldSchema(name="id", dtype=DataType.INT64, is_primary=True, auto_id=True),
    FieldSchema(name="title", dtype=DataType.VARCHAR, max_length=512),
    FieldSchema(name="embedding", dtype=DataType.FLOAT_VECTOR, dim=768),
    FieldSchema(name="category", dtype=DataType.VARCHAR, max_length=64),
    FieldSchema(name="score", dtype=DataType.FLOAT),
]

schema = CollectionSchema(fields, description="文档知识库")
collection = Collection("documents", schema)

# --- 创建索引 ---
index_params = {
    "index_type": "HNSW",
    "metric_type": "COSINE",
    "params": {
        "M": 16,
        "efConstruction": 200
    }
}
collection.create_index("embedding", index_params)

# --- 批量插入数据 ---
NUM_DOCS = 100_000
BATCH_SIZE = 1000

for i in range(0, NUM_DOCS, BATCH_SIZE):
    batch_size = min(BATCH_SIZE, NUM_DOCS - i)
    data = [
        [f"文档标题 {j}" for j in range(i, i + batch_size)],
        [np.random.rand(768).tolist() for _ in range(batch_size)],
        [np.random.choice(["tech", "science", "history"]) for _ in range(batch_size)],
        [float(np.random.randint(0, 100)) for _ in range(batch_size)],
    ]
    collection.insert(data)

collection.flush()
print(f"已插入 {collection.num_entities} 条数据")

# --- 加载到内存并搜索 ---
collection.load()

query_vector = np.random.rand(768).tolist()

results = collection.search(
    data=[query_vector],
    anns_field="embedding",
    param={"metric_type": "COSINE", "params": {"ef": 100}},
    limit=10,
    expr='category == "tech" and score > 50',  # 标量过滤
    output_fields=["title", "category", "score"]
)

for hits in results:
    for hit in hits:
        print(f"ID: {hit.id}, 距离: {hit.distance:.4f}, "
              f"标题: {hit.entity.get('title')}, "
              f"类别: {hit.entity.get('category')}")
```

# 1. 分区（Partition）—— 物理隔离数据，加速过滤

    FieldSchema(name="title_vec", dtype=DataType.FLOAT_VECTOR, dim=384),

]

# 3. 动态 Schema —— 不需要预定义所有字段

### pgvector——PostgreSQL 的向量扩展

**一句话**：在你已有的 PostgreSQL 中直接获得向量搜索能力，零新基础设施。

**适用场景**：已有 PostgreSQL、数据量 < 500 万、不想引入新组件。

**不适用场景**：超大规模数据、需要极致搜索性能。

```sql
-- 1. 安装扩展
CREATE EXTENSION IF NOT EXISTS vector;

-- 2. 创建表
CREATE TABLE documents (
    id SERIAL PRIMARY KEY,
    content TEXT NOT NULL,
    metadata JSONB DEFAULT '{}',
    embedding vector(1536)
);

-- 3. 插入数据
INSERT INTO documents (content, embedding) VALUES
('向量数据库是 AI 应用的基础设施', '[0.023, -0.156, ...]'::vector),
('PostgreSQL 是世界上最流行的开源关系型数据库', '[0.089, 0.234, ...]'::vector);

-- 4. 创建 HNSW 索引
CREATE INDEX ON documents USING hnsw (embedding vector_cosine_ops)
    WITH (m = 16, ef_construction = 200);

-- 5. 查询：找到最相似的 5 条记录
SELECT id, content,
       1 - (embedding <=> '[0.023, -0.156, ...]'::vector) AS similarity
FROM documents
ORDER BY embedding <=> '[0.023, -0.156, ...]'::vector
LIMIT 5;

-- 6. 结合 SQL 条件过滤
SELECT id, content,
       1 - (embedding <=> $1::vector) AS similarity
FROM documents
WHERE metadata->>'category' = 'technology'
  AND created_at > NOW() - INTERVAL '30 days'
ORDER BY embedding <=> $1::vector
LIMIT 5;

-- 7. 设置搜索参数（运行时调整）
SET hnsw.ef_search = 100;  -- 提高召回率
```

```python
# Python 中使用 psycopg2 + pgvector
import psycopg2
from pgvector.psycopg2 import register_vector

conn = psycopg2.connect("dbname=mydb")
register_vector(conn)

cur = conn.cursor()

query_embedding = [0.023, -0.156, ...]  # 1536 维
cur.execute("""
    SELECT id, content, 1 - (embedding <=> %s::vector) AS similarity
    FROM documents
    WHERE metadata->>'category' = 'technology'
    ORDER BY embedding <=> %s::vector
    LIMIT 5
""", (query_embedding, query_embedding))

for row in cur.fetchall():
    print(f"ID: {row[0]}, 相似度: {row[2]:.4f}")
```

**pgvector 独特优势**：

```sql
-- 1. 与 SQL 完美融合 —— 向量搜索 + 关联查询 + 聚合
SELECT d.content, u.username,
       1 - (d.embedding <=> $1::vector) AS similarity
FROM documents d
JOIN users u ON d.author_id = u.id
WHERE d.status = 'published'
ORDER BY d.embedding <=> $1::vector
LIMIT 10;

-- 2. 事务支持 —— 向量数据与其他业务数据在同一个事务中
BEGIN;
UPDATE documents SET embedding = $1 WHERE id = 42;
INSERT INTO audit_log (action, doc_id) VALUES ('update_embedding', 42);
COMMIT;

-- 3. 索引类型选择
-- HNSW 索引（推荐，查询更快）
CREATE INDEX ON documents USING hnsw (embedding vector_cosine_ops);
-- IVFFlat 索引（构建更快，适合批量导入场景）
CREATE INDEX ON documents USING ivfflat (embedding vector_cosine_ops)
    WITH (lists = 100);

-- 4. 支持多种向量类型
-- 半精度（float16）节省空间
ALTER TABLE documents ADD COLUMN embedding_half halfvec(1536);
-- 二进制向量（用于 Hamming 距离）
ALTER TABLE documents ADD COLUMN embedding_bit bit(1536);
```

**pgvector 调优要点**：

```sql
-- 根据数据量调整 HNSW 参数
-- 数据量 < 100万: m=16, ef_construction=200（默认）
-- 数据量 100万-1000万: m=32, ef_construction=400
-- 数据量 > 1000万: 考虑使用专业向量数据库

-- 查询时提高召回率
SET hnsw.ef_search = 200;  -- 默认 40，生产环境建议 100+

-- 监控索引大小
SELECT pg_size_pretty(pg_relation_size('documents_embedding_idx'));
```


### Weaviate——混合搜索之王

**一句话**：内置 BM25 + 向量融合的混合搜索，GraphQL API 友好。

**适用场景**：需要同时做语义搜索和关键词搜索、偏好 GraphQL。

```bash

docker run -p 8080:8080 \
    -e QUERY_DEFAULTS_LIMIT=25 \
    -e AUTHENTICATION_ANONYMOUS_ACCESS_ENABLED=true \
    -e PERSISTENCE_DATA_PATH='/var/lib/weaviate' \
    semitechnologies/weaviate:latest
```

```python
import weaviate

client = weaviate.Client("http://localhost:8080")

# 1. 创建 Schema
schema = {
    "classes": [{
        "class": "Document",
        "vectorizer": "text2vec-transformers",  # 使用本地 embedding 模型
        "properties": [
            {"name": "content", "dataType": ["text"]},
            {"name": "category", "dataType": ["string"]},
            {"name": "score", "dataType": ["number"]},
        ]
    }]
}
client.schema.create(schema)

# 2. 插入数据
client.data_object.create(
    {"content": "Qdrant 是 Rust 实现的向量数据库", "category": "database", "score": 95},
    "Document"
)

# 3. 混合搜索（Weaviate 的杀手锏）
results = (
    client.query
    .get("Document", ["content", "category"])
    .with_hybrid(
        query="向量数据库性能优化",
        alpha=0.75  # 0=纯关键词, 1=纯向量, 0.75=偏语义
    )
    .with_limit(5)
    .do()
)

# 4. 也支持纯向量搜索
results = (
    client.query
    .get("Document", ["content"])
    .with_near_vector({"vector": query_embedding})
    .with_where({
        "path": ["category"],
        "operator": "Equal",
        "valueText": "database"
    })
    .with_limit(5)
    .do()
)
```


### Pinecone——零运维全托管

**一句话**：无需部署、无需调优，API 即用即走。

**适用场景**：不想运维、快速上线、中小规模。

**不适用场景**：数据主权要求高、需要深度定制、成本敏感。

```bash
pip install pinecone-client openai
```

```python
from pinecone import Pinecone, ServerlessSpec
from openai import OpenAI

# 1. 初始化
pc = Pinecone(api_key="YOUR_API_KEY")
openai_client = OpenAI()

# 2. 创建索引
index_name = "knowledge-base"
if index_name not in pc.list_indexes().names():
    pc.create_index(
        name=index_name,
        dimension=1536,
        metric="cosine",
        spec=ServerlessSpec(cloud="aws", region="us-east-1")
    )

index = pc.Index(index_name)

# 3. 插入数据
def get_embedding(text: str) -> list[float]:
    response = openai_client.embeddings.create(
        model="text-embedding-3-small", input=text
    )
    return response.data[0].embedding

vectors = [
    {
        "id": "doc1",
        "values": get_embedding("Pinecone 是全托管向量数据库"),
        "metadata": {"category": "database", "source": "docs/pinecone.md"}
    },
    {
        "id": "doc2",
        "values": get_embedding("RAG 通过检索增强生成质量"),
        "metadata": {"category": "ai", "source": "docs/rag.md"}
    }
]
index.upsert(vectors=vectors)

# 4. 查询
query_embedding = get_embedding("向量数据库如何工作")
results = index.query(
    vector=query_embedding,
    top_k=5,
    include_metadata=True,
    filter={"category": {"$eq": "database"}}  # 元数据过滤
)

for match in results["matches"]:
    print(f"ID: {match['id']}, 分数: {match['score']:.4f}")
```


## RAG 完整示例

以下是使用 Qdrant 构建生产级 RAG 系统的完整示例：

```python
from qdrant_client import QdrantClient
from qdrant_client.models import Distance, VectorParams, PointStruct, Filter, FieldCondition, MatchValue
from openai import OpenAI

qdrant = QdrantClient("localhost", port=6333)
openai_client = OpenAI()

COLLECTION_NAME = "knowledge_base"

# --- 1. 创建集合 ---
qdrant.recreate_collection(
    collection_name=COLLECTION_NAME,
    vectors_config=VectorParams(size=1536, distance=Distance.COSINE)
)

# --- 2. 数据准备与插入 ---
def get_embedding(text: str) -> list[float]:
    response = openai_client.embeddings.create(
        model="text-embedding-3-small", input=text
    )
    return response.data[0].embedding

documents = [
    {"id": 1, "text": "Qdrant 是一个用 Rust 编写的高性能向量数据库。", "source": "qdrant-intro.md", "category": "database"},
    {"id": 2, "text": "RAG 通过在生成前检索相关文档来增强大语言模型的回答质量。", "source": "rag-overview.md", "category": "ai"},
    {"id": 3, "text": "HNSW 算法通过构建多层可导航小世界图来实现高效的近似最近邻搜索。", "source": "hnsw-algorithm.md", "category": "algorithm"},
]

points = []
for doc in documents:
    embedding = get_embedding(doc["text"])
    points.append(PointStruct(
        id=doc["id"],
        vector=embedding,
        payload={"text": doc["text"], "source": doc["source"], "category": doc["category"]}
    ))

qdrant.upsert(collection_name=COLLECTION_NAME, points=points)

# --- 3. RAG 查询函数 ---
def rag_query(question: str, top_k: int = 3) -> str:
    """RAG 流程：检索 → 增强 → 生成"""
    query_vector = get_embedding(question)

    search_results = qdrant.search(
        collection_name=COLLECTION_NAME,
        query_vector=query_vector,
        limit=top_k,
        query_filter=Filter(must=[
            FieldCondition(key="category", match=MatchValue(value="ai"))
        ])
    )

    context = "\n\n".join([
        f"[来源: {hit.payload['source']}]\n{hit.payload['text']}"
        for hit in search_results
    ])

    response = openai_client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[
            {"role": "system", "content": "你是一个知识助手。根据提供的参考资料回答问题。如果参考资料中没有相关信息，请如实说明。"},
            {"role": "user", "content": f"参考资料:\n{context}\n\n问题: {question}"}
        ]
    )
    return response.choices[0].message.content

# 使用
answer = rag_query("什么是 RAG？它是怎么工作的？")
print(answer)
```

# 手动融合（适用于任何向量数据库）
def hybrid_search(query_text: str, query_vector: list, alpha: float = 0.7):
    semantic_results = collection.query(query_vector=query_vector, n_results=100)
    keyword_results = collection.query(query_texts=[query_text], n_results=100,
                                       where_document={"$contains": query_text.split()[0]})

    scores = {}
    for rank, doc_id in enumerate(semantic_results["ids"][0]):
        scores[doc_id] = scores.get(doc_id, 0) + alpha / (60 + rank)
    for rank, doc_id in enumerate(keyword_results["ids"][0]):
        scores[doc_id] = scores.get(doc_id, 0) + (1 - alpha) / (60 + rank)

    return sorted(scores.items(), key=lambda x: x[1], reverse=True)[:10]

## 常见问题

### Q: 向量数据库和传统数据库有什么区别？

传统数据库针对**结构化数据**和**精确查询**优化，使用 B-tree 索引。向量数据库针对**高维向量**和**相似性搜索**优化，使用 HNSW、IVF 等专用索引。两者是互补关系。

PostgreSQL 通过 pgvector 获得了向量搜索能力，但对于小规模场景（< 100 万向量）完全够用；大规模、高性能场景仍需专业向量数据库。

### Q: pgvector 够用吗？

取决于规模：

| 数据量 | pgvector 是否够用 | 建议 |
|--------|-------------------|------|
| < 100 万 | ✅ 完全够用 | 直接用 pgvector |
| 100 万 - 500 万 | ✅ 够用（需调优） | 调大 `ef_search`，监控查询延迟 |
| 500 万 - 1000 万 | ⚠️ 勉强 | 考虑迁移到专业方案 |
| > 1000 万 | ❌ 不推荐 | 使用 Qdrant / Milvus |

### Q: 如何从一个向量数据库迁移到另一个？

目前没有通用的迁移工具。推荐做法：

1. 保留原始文本（不只是向量）
2. 用原始文本重新 embedding 并导入新数据库
3. 如果维度和度量兼容，可以直接导出/导入向量数据

### Q: 成本怎么算？

| 方案 | 小规模（< 100万） | 中等（100万-1000万） | 大规模（> 1000万） |
|------|-------------------|---------------------|-------------------|
| **Chroma** | 免费 | N/A | N/A |
| **pgvector** | 已有 PG 的边际成本 ≈ 0 | PG 服务器成本 | 需要高配 PG |
| **Qdrant Cloud** | ~$25/月 | ~$100-300/月 | ~$500+/月 |
| **Pinecone** | 免费层可用 | ~$70-200/月 | ~$500+/月 |
| **Milvus (自托管)** | 服务器成本 | 集群成本 | 多节点集群成本 |

## 总结

选向量数据库就像选编程语言——没有"最好"，只有"最合适"。Chroma 帮你 5 分钟上手，pgvector 让你在已有基础设施上无缝扩展，Qdrant 在性能和易用性之间取得了最佳平衡，Milvus 为亿级数据提供了成熟的分布式方案，Pinecone 则让你完全不用操心运维。

关键原则：**先用简单的跑通，再按需升级**。从 Chroma 或 pgvector 开始验证你的 RAG 应用，等到数据量或性能要求超出它们的能力时，再迁移到 Qdrant 或 Milvus。迁移的成本远低于一开始就搭建复杂分布式系统的成本。
