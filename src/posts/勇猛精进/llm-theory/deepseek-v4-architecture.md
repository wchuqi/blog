DeepSeek V4 是当前开源模型中的第一名（open source model number one）。它与 GPT、豆包这些日常工具同属一个技术体系，整体可分为四层结构：**模型架构**、**训练**、**优化系统**和 **Agent**。V4 把目前的主流技术全部整合了上去。

下面以一个具体场景展开：假设模型输入了一段包含 100 万 token 的长文本，现在准备生成下一个 token。

## 一、KV Cache：为什么需要它

复习一下 Attention 的基本原理。每个 token 进来都会生成三个向量：

- **Q（Query）**：查询向量
- **K（Key）**：索引
- **V（Value）**：token 能提供的信息

当前 token 的 Q 会与已存在 token 的 K 做点积，计算二者的关联程度，再根据相关性决定提取多少 V——也就是"用 Q 找 K，提取 Value"。

问题在于：每次生成新 token 时，如果都要重新计算前面 100 万个 token 的 K 和 V，非常浪费算力。观察三个向量的性质：

- Q 是临时检索词，用完就没用了；
- 只有 K 和 V 携带真正有用的信息，之后的每个 token 都可能把之前的 KV 翻出来用。

所以只需把每个 token 的 KV 向量保存下来即可，这就是 **KV Cache**。

但普通 Transformer 有两个痛点：

1. 每个 token 都要和其他 token 相乘，需要存储大量 KV，**显存占用很大**；
2. 需要不断从显存读取这些 KV，**访存开销也很大**。

这就是 DeepSeek V4 在架构上第一个创新点的出发点。

## 二、混合注意力机制：CSA + HCA

### CSA（轻度块压缩）

把 100 万个 token 分成很多块，每块包含若干个 token，然后把每一块内所有 token 的 KV 向量压缩。例如一个块里有 8 个 token，按理应有 8 组 K 和 8 组 V，现在只用 2 组 KV 就能表示这 8 个 token。压缩方式有很多种，比如量化（磁化）或可学习压缩等。

当前待预测 token 的 Q 与每一个块的 K 计算相似度，再提取对应的 V。

### HCA（重度压缩）

HCA 比 CSA 压缩得更狠：分组时每个块包含更多 token，用更少的 KV 表示。打个比方：

- CSA 像"段落摘要"，至少还保留一些细节信息；
- HCA 像"全文摘要"，只保留最核心的全局背景。

### 效果

官方数据：同样处理 100 万 token，V4 生成下一个 token 所需的计算量约为上一代的 **27%**，KV Cache 只有上一代的 **10%**。这样既抓住了关键内容，也保留了全局背景，还大幅减少了计算和显存。

## 三、MHC：多状态混合连接

特征提取完成后，信息要在深层网络中传输。普通 Transformer 使用残差连接：输入 x 经过 MLP 得到 y，往下传时还要加上之前的 x。一直这么传到后面，第一层的有效信息容易被稀释掉。（Kimi 的注意力残差也是针对这个问题的解决方案之一。）

DeepSeek V4 采用 **MHC** 方案：

1. 把输入 x 复制几份一模一样的副本；
2. 每份乘以一个可随训练学习的参数矩阵，避免所有信息都混进同一个 token——比如第一份表示该 token 的局部信息，第二份表示长期信息；
3. 信息混合之后乘一个可学习矩阵，让模型自己学习"复制"或"读取"哪几份往下传；继续下传时同样乘以可学习矩阵。

### 稳定性约束

既然引入了可学习矩阵，就容易出现梯度爆炸和梯度消失的问题。解决办法是给矩阵加约束：让矩阵**非负，且行和列之和为 1**。

这样 MHC 就能实现多状态混合并保持稳定，让早期信息稳定地传递下去。这个设计思路在实际工程中也可以借鉴。

## 四、MoE：混合专家系统

DeepSeek V4 还使用了 MoE（Mixture of Experts），这是比较常见的技术：

- MoE 层包含多个并行的小网络（专家），每个专家负责一部分任务，比如一个负责数学、一个负责代码；
- 每个 token 进入 MoE 层后，先经过 **Router（路由层）**：Router 给每个专家打分，选出分数最高的 k 个专家来处理这个 token。道理很简单：如果 token 是工科专业词汇，用心理学专家去分析毫无意义——这是在节约算力。

V4 的改进点在于专家的分工：通俗地讲，每个专家都接受过"九年义务教育"，具备一些通用能力。为了让专家更加专精，V4 把通用能力单独交给另一个网络——**通识网络**。所以每个 token 经过 Attention 和 MHC 之后，会先经过通识专家网络，再由 Router 选出若干专业专家处理。

这样做的效果是每个 token 的实际计算量可控。

## 五、MTP：多 token 预测

训练层面，V4 引入了 MTP（Multi-Token Prediction）创新。

- **普通大模型训练**：看见一个词，预测下一个词。词表有 1 万个 token 时，输出对应 1 万个 token 的概率分布，取概率最高的输出。比如输入"你没活"，预测"干"，然后循环。
- **MTP**：看见一个词后，把后面所有的词全都预测出来。它是多个预测词表并行——输入"你没活"，MTP 输出两个词表：一个负责预测第 4 个字"干"，一个预测第 5 个字"吧"。每个词表内部仍然包含很多个 token 及其对应分数。

这让模型学会"多布局"，对长文本理解和推理能力有很大帮助。

## 总结

面对 100 万级长上下文：

| 问题 | V4 方案 |
| --- | --- |
| 历史 token 过长，Q 匹配大量历史 K 计算量爆炸 | CSA 轻度压缩 + HCA 重度压缩，兼顾细节与全局 |
| 深层网络中早期信息被稀释 | MHC 多状态混合，配合非负归一化矩阵保证稳定传输 |
| 每 token 实际计算量不可控 | DeepSeek MoE + 通识网络 + Router 选择性激活 |
| 训练只学单步预测 | MTP 多 token 预测，提升长文本与推理能力 |
