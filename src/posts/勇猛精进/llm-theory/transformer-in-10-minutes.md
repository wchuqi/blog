2017 年那篇《Attention Is All You Need》，是今天 GPT、DeepSeek 等一切大模型的起点。没有它就没有 Transformer 架构。下面从翻译问题出发，把它的原理走一遍。

## 从翻译问题说起

以"呼啦啦拉布拉拉布拉多"为例：短短十个字里有六个"拉"字，人类一眼就能理解并翻译成英文（Can 呼啦啦 carry 拉布拉多）。关键在于**理解**。

但计算机很难理解：每个"拉"字在不同位置含义不同——中间的"拉布"里，"拉"在中文里可以表示拉货，也可以表示拉扯；在英文里既可以翻译为 carry，也可以是 drag 或 pull。必须结合前面的"货拉拉"和后面的"拉布拉多"才能准确理解。

问题来了：计算机该如何理解一句话里每个词的含义？

## Token 与 Embedding

计算机只认识 0 和 1，翻译之前需要把文本变成数字。

最简单的方法是把文本转成数字编号（如 unicode 编码），但编号只是纯数字，不承载任何语义信息，两个编号之间也没有语义关联。

我们需要一种既能数字化又能承载语义的方案：

1. 把这句话切分成多个词块，每个词块叫一个 **token**；
2. 想象一个坐标系：x 轴表示是否与交通相关、y 轴表示是否与动物相关。"货拉拉"落在 x 正方向，"拉布拉多"落在 y 正方向；"物流平台""网约车"更靠近货拉拉，"金毛""牧羊犬"更靠近拉布拉多。

但两个维度不够。比如加入第三维"是否运货"，货拉拉和物流平台偏向运货，网约车偏向运人，它们就被区分开了。随着维度增多，世界上所有词汇的 token 都能在这个多维坐标系中找到自己的位置。通过海量语料训练后，**语义相近的词靠得很近，语义无关的词离得很远**。

词与词之间的关系还能用数学计算：比如"国王的坐标 − 男人的坐标 + 女人的坐标 ≈ 王后的坐标"。多义词（如"拉布"）在坐标系里只是一个模糊的平均位置，只有结合上下文之后，位置才会被拉向正确的语义区域。

每个坐标维度都是数字，所以每个 token 都可以用一组数字表示——这就是 **embedding（向量）**。

语言不仅有语义还有顺序："货拉拉"和"拉拉货"意思完全不同。所以模型还会为每个 token 加入**位置信息**，让向量同时包含"它是什么"和"它在什么位置"。

## QKV 是什么

理解了向量，就可以考虑翻译了。新问题：翻译"拉布"这种多义词时，怎么结合上下文判断这个"拉"究竟是 carry 还是 drag？

每个词块除了字面意思，背后还有含义（如"拉布拉多"背后的含义有宠物狗等）。可以把一句话抽象成一个**词块数据库**：查询键 key 就是词块本身，value 就是词块背后的含义。理解"拉布"时该关注哪些词，就相当于拿着"拉布"去词块数据库里挨个遍历，看哪个词对它参考价值更大。

这里有三个概念：查询（Query）、键（Key）、值（Value）。直接拿同一个 token 向量扮演三个角色不够灵活，所以通过三个权重矩阵 Wq、Wk、Wv 变换，让每个 token 的向量变成三个专门向量，各司其职：

- **Q**：这个 token 想关注什么，像数据库的查询语句；
- **K**：这个 token 能提供什么信息，像数据库的查询键；
- **V**：这个 token 背后的真正含义，像查询键对应的值。

## 注意力机制

有了每个 token 的 QKV，计算过程如下：

1. **点积求相关度**：每个 token 的 Q 遍历句子中所有 token 的 K，做点积。点积就是相乘——从数学上看是计算两个向量方向是否一致，越同向数值越大；从效果上看，相关程度越高，这个 token 越值得被重点参考。
2. **Scale 缩放**：如果向量维度较大，点积结果可能整体偏大，导致某个 token 的关注度被放大得过于极端。除以维度的开方 √dk，让不同 token 之间的关注差异更容易区分。
3. **Softmax 归一**：对关注程度做 softmax，转成一组权重，所有权重之和为 1——即注意力分配比例。
4. **加权求和 V**：用这组权重对所有 token 的 V 向量加权，得到的结果就是该 token 融合上下文信息之后的表示。

整套流程就是**注意力机制**，公式为 `softmax(QKᵀ/√dk)V`。它让每个 token 根据当前语境自动决定应该重点参考其他哪些 token。

小结：

| 步骤 | 作用 |
| --- | --- |
| QK 点积 | 计算 token 之间"关注谁、关注程度" |
| Scale | 防止点积过大导致 softmax 饱和、梯度消失，训练更稳定 |
| Softmax | 把关注程度转换成注意力权重（概率分布） |
| 乘 V | 按权重从被关注的 token 中提取并融合语义内容 |

## 多头注意力

只算一次注意力不够：词与词之间的关系是多样的——有的是语义关联，有的是语法结构依赖，单一角度难以捕捉全面。所以模型会**并行做多次注意力计算**，每次关注不同侧重点，最后把结果拼接在一起。这就是**多头注意力**。

## Add & Norm

通过多头注意力，原句的语义信息被表示成了向量。接着：

- **Add（残差连接）**：把注意力结果与原始输入相加，确保 token 自身的信息不被覆盖；
- **Norm（归一化）**：对结果做统一调整，使数值保持在稳定范围，既保留原有信息，又避免数值在多层计算后失控。

## 前馈网络（FFN）

经过残差连接和归一化后，从输入到输出的映射仍是线性的——可以理解为变换路径都是笔直的直线，无法捕捉自然语言里非线性的复杂语义关联。

前馈网络（FFN）的核心作用是通过 **ReLU 等激活函数**，把线性的映射路径"掰弯"，变成非线性的曲线。随后同样再接一次 Add 和 Norm。

## 编码器

多头注意力 → Add&Norm → 前馈网络 → 再一次 Add&Norm，共同构成一个**编码层**。一个编码层能让模型对整句话形成一次上下文理解；多个编码层堆叠起来，语义理解逐层加深，组成完整的**编码器**。

编码器的最终输出是一组向量：原句各个词块融合上下文语义之后的数字表现形式，也就是计算机对输入文本的整体语义理解。

## 解码器与翻译原理

基于编码器输出的整体语义理解开始生成英文。先放入固定的起始符号 BOS，模型结合编码器输出预测第一个英文词（如 can）；再把 BOS 和 can 作为输入预测下一个词，以此类推——每一步都像成语接龙。

生成过程要解决两个问题，都用注意力解决：

### 1. 保证已生成内容的连贯 —— 带掩码的多头自注意力

Q 是当前要预测单词的位置；既然要保证衔接自然连贯，模型只需关注已经生成的英文，所以 KV 来自英文构成的词块数据库。预测第 n 个词时只依赖前 n−1 个词的结果，就像掩盖了后面部分做词语预测一样，因此叫**带掩码（masked）的多头自注意力**。

### 2. 决定参考原句哪部分 —— 多头交叉注意力

Q 是当前要预测单词的位置，KV 来自中文构成的词块数据库。比如已生成"can 货拉拉"、正在翻译"拉布"时，由于编码器输出的中文理解中它与运货相关信息关联更强，就更可能译为 carry 而不是 pull 或 drag。这部分叫**多头交叉注意力**。

这两次注意力的输出同样经过残差网络、归一化和前馈网络，构成一个解码层；多层堆叠形成完整**解码器**。最终解码器输出的向量通过词表转成可读文字输出。

## 三种架构形态

编码器和解码器配合完成翻译，这是 Transformer 的经典架构。但实际上并非所有任务都需要二者同时存在：

- **只用编码器**：只需理解文本、不需生成的任务，如 BERT，用于文本分类、情感分析这类理解任务；
- **纯解码器架构**：ChatGPT、DeepSeek 这类大模型直接把用户输入交给解码器做理解，然后逐词生成内容，省略了独立编码器；
- **编码器 + 解码器**：完整架构后续主要用于小模型和低资源场景。
