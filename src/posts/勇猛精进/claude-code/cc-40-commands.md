> 演讲者：Boris，Anthropic 技术团队成员，Claude Code 开发者。以下为 30 分钟官方实操分享的整理。

## Claude Code 是什么

Claude Code 是一款全自主代理（agentic）编程助手，不同于只做逐行补全的旧工具：它能一次性编写完整的函数和文件，甚至直接修复整个 bug。

- 无缝适配现有工具链：VS Code、Xcode、JetBrains 系列 IDE 都能用，无需替换任何现有工具
- 本地、远程 SSH、tmux 中均可顺畅运行
- 零配置：下载启动即可使用，不做索引、不上传代码库，代码本地存储且不用于训练模型

## 安装与初始设置

- 安装依赖 Node.js
- 终端设置中启用后可用 `Shift+Enter` 换行，无需输入反斜杠
- `/theme`：切换浅色 / 深色 / 灰暗主题
- `/install-github-app`：安装 GitHub 应用，可在任意 issue 或 pull request 中直接 @ Claude
- 权限白名单：把常用的、总是弹窗确认的工具提前设为允许，免去每次手动确认
- macOS 用户可开启系统设置 → 辅助功能 → 听写，双击听写键直接口述提示词；提示越具体越好

## 入门第一课：代码库问答

Anthropic 内部培训新人的第一课就是向代码库提问——技术新人入职从过去两三周缩短至两三天。

- 直接问"这段代码是怎么用的""这个对象该怎么实例化"，它会主动深挖类的实例化和实际用法，而不只是文本搜索
- 可分析 git 历史：弄清某个函数的 15 个参数怎么来的、谁改的、当时什么情况、关联了哪些 issue，只需说"查看 git 历史"
- 用 WebFetch 拉取 GitHub issue 及相关背景
- 例：每周一站会复盘交付成果——它自动查阅日志、识别用户名、生成本周交付清单

新手建议：先从代码库问答开始，别急着用花哨功能或直接改代码。这样既能学会写提示词，又能摸索出能力边界。

## 编辑代码与工作流

Claude Code 只提供少量工具（文件编辑、运行 bash 命令、搜索文件），但会自行组合完成探索、构思到修改的全过程，无需指定用哪个工具。

推荐工作流：

1. **先规划再动手**："写代码前先规划"。让 Claude 先头脑风暴、做计划，等你批准后再写代码。不建议上来就丢一个 3000 行的功能让它直接实现
2. **提交推送提 PR**：一句话即可，它会自动扫代码、读 git 日志摸清提交格式，然后提交、推送、建分支、提 PR
3. **接入团队工具**：
   - CLI 工具：告知它工具的存在，它能像执行 `--help` 一样自行摸索用法；高频使用的可存入 CLAUDE.md
   - MCP 工具：添加 MCP 工具并说明用法即可上手
4. **给反馈让它自验证迭代**：单元测试、Puppeteer 截图、iOS 模拟器等。给它设计稿让它实现界面并配 Puppeteer 服务器反复迭代调试，通常两三轮就近乎完美。关键是给它一个能自我检验结果的工具

## 上下文管理：CLAUDE.md 与斜杠命令

上下文越充分，决策越精准。给上下文的层级化方式：

| 层级 | 说明 |
| --- | --- |
| 项目 CLAUDE.md | 放在项目根目录，会话开始自动载入，建议提交共享给团队 |
| 本地 CLAUDE.md | 个人使用，无需提交版本控制，写入常用 bash 命令、MCP 工具、架构决策、关键文件 |
| 嵌套子目录的 CLAUDE.md | Claude 在这些目录内工作时自动载入 |
| 企业级策略 | 放在企业根目录，跨所有代码库统一管理、自动下发全员 |

要点：

- 内容尽量简短，太长只会白白消耗上下文
- 斜杠命令既可存于主目录也可存入项目。例：Anthropic 仓库里 issue 自动打标，就是通过 GitHub Action 跑一条斜杠命令实现的
- 权限也能分层配置：把通用测试命令迁入企业策略文件即全员自动获批；反向也能禁止抓取某个 URL，员工无法覆盖
- MCP 服务器只需建个 JSON 文件提交进代码库，任何人运行 Claude Code 时都会提示安装。例：Anthropic 全团队共用仓库里的 Puppeteer MCP 跑端到端测试
- `/memory`：查看所有正在加载的记忆文件（企业策略、用户记忆、项目记忆、嵌套配置），也可用它编辑特定记忆文件
- `#` 开头输入内容：记录到记忆，可选择存入哪个记忆库

不知道从哪入手时，建议先配共享项目上下文——配置一次全队受益，有网络效应。

## 快捷键速查

| 快捷键 / 命令 | 功能 |
| --- | --- |
| `Shift+Tab` | 进入自动接受编辑模式（bash 命令仍需确认，代码改动自动应用，随时可撤回） |
| `#` | 记住某件事（如纠正工具使用方式），整合进 CLAUDE.md |
| `!` + 命令 | bash 模式：本地运行命令并把输出同步进上下文窗口，适合耗时长的命令 |
| `@` | 引用任意文件或文件夹 |
| `Esc` | 中断 Claude，随时安全，不会弄坏会话；可指出哪里要重做 |
| 双击 `Esc` | 回溯历史 |
| `--resume` 或 `--continue` | 会话结束后恢复会话 |
| `Ctrl+R` | 查看完整输出（即 Claude 在上下文窗口中所见的内容） |

## Claude Code SDK

加 `-p` 参数就是在使用 SDK：

```bash
claude -p "提示词" --allowedTools ... --output-format json
```

- 可传入提示词、指定允许使用的工具（含特定 bash 命令）、自定义输出格式（普通 JSON 或流式 JSON）
- 当 Unix 工具用：给个提示回你 JSON，进出皆可管道化，适合 CI、事故响应、各类流水线
- 组合示例：`git status` 输出管道传给 jq 提取结果再喂给它；从 GCP 存储桶拉海量日志管道传入让它甄别关键信息；从 Sentry 拉取数据交由它处理

## 高阶玩法：并行会话

重度用户的常见做法：

- 通过 SSH 会话配合 tmux 接入
- 检出同一仓库的多个副本并行运行多个 Claude 会话
- 借助 `git worktrees` 在操作过程中实现隔离

## Q&A 要点

- **最难的技术难点**：bash 命令的安全执行。方案是静态分析甄别只读命令 + 多级权限系统分层管控黑白名单
- **多模态**：从一开始就支持，直接拖图片进终端或给文件路径、复制粘贴都行。常见用法是拖入界面设计稿让它实现并配 Puppeteer 自动迭代
- **为什么做终端而不是 IDE**：一是团队 IDE 太多元（VS Code / Xcode / Vim / Emacs），终端是唯一共同选择；二是模型能力进化太快，年底大家可能就不用 IDE 了，不应在 UI 上层过度投入
- **内部使用率**：Anthropic 大约八成技术人员每天都在用 Claude Code，包括用 notebook 的研究人员
