## 背景

这是来自 Vercel 的一篇文章，发表于 2025 年 12 月 22 日。他们在为 v0 做 Text2SQL 的 Agent，花了很长时间使用特定的工具、很重的提示词工程以及上下文工程的手段，但整个设计完成后效果并不好。

## 第一版 Agent：几十个工具

第一版给 Agent 配了好多十个专用工具，包括：

- 实体（entity）查找
- Schema 查找
- 后置验证
- 各种与 SQL 执行相关的方式

设计过程中发现：越设计越脆弱，越设计越需要人工维护，效果并不好。

## 新方案：只留一个 Bash

他们尝试把该砍掉的都砍掉，最后只留下单一的一个入口：Bash。Shell 里只用 `grep`、`cat`、`ls` 这类基础的 Unix 命令，用于读取和检索文件系统中的**语义层**描述信息。

语义层是数据库层非常重要的一环：它把底层的数据和上层的业务进行对接，可以理解为业务指标对 SQL 底层数据的描述信息。所有这些描述信息都以文件的形式存在，Agent 通过这几个基础命令去读取和操作文件系统，让模型自己去思考什么时候应该做哪些动作、什么时候应该执行什么。

## 结果

- 速度提升 **3.5 倍**
- Token 减少 **37%**
- 准确度从 80% 提升到 **100%**

## 四点启发

1. 我们构建的许多工具，Unix 也许早就解决了，不要重复造轮子。
2. 如果给模型写了很多提示词去规定推理方向，有可能反而限制住了模型做出更好的选择。
3. 语义层（文档、上下文描述）做得好非常关键，让模型理解这些描述再去执行相关命令。
4. **最佳的 Agent 是使用最少工具的 Agent。**

## 构建 Agent 的指导原则

- 一定要从最简单的架构开始：模型 + 操作系统 + 目标，从这个阶段开始构建 Agent。
- 确实需要更复杂的东西时，才引入复杂的提示词、复杂的流程和描述。
- 简单的架构并不是全部：要投入大量时间去打磨文档修正、清晰的命名、良好的组织和完善的数据结构——这些是你能给到模型的最佳内容，模型会借助这些内容更好地完成任务。
